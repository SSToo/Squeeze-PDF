Confirm that you have the right to submit the code, and retain third-party copyrights, provenance and licenses. Do not relicense third-party material as project code.

## Development environment

Requires Node.js 22.13+, Rust 1.92.0 and a platform C compiler. Install Xcode Command Line Tools on macOS, or MSVC C++ Build Tools and WebView2 on Windows. See the [README](README.md) for full build and packaging commands.

```sh
npm ci
npm run tauri -- dev
```

`npm ci` prepares the pinned PDF.js assets. Build scripts generate the CLI, desktop worker and third-party materials. The npm package's `private: true` prevents accidental publication to npm; it does not affect the project's open-source license.

## Validating changes

Engine changes should cover the relevant modes, presets, fallbacks and input protections. Compare complete PDFs rather than judging final size from intermediate encoded streams. Changes affecting quality or content require independent-reader checks; describe exactly what was checked. See the README for the content behavior of preserve and image modes.

```sh
node scripts/prepare-worker.mjs
npm run notices
npm run test:licenses
npm run check
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

For frontend rendering or language changes, also run `npm run test:render` and `npm run test:i18n`. CI checks and packages Windows x64, macOS arm64 and macOS Intel builds. Local test results do not replace installation acceptance tests on other platforms.

Changes to automatic publishing or installer collection require `node --test scripts/test-release.mjs`. See the [release guide](docs/RELEASING.md) for version-tag publishing.

Some independent quality-check scripts require Python and additional PDF/image tools. `desktop-raster-baseline.mjs` uses `python3` from PATH by default; set `SQUEEZE_QA_PYTHON` to an interpreter with the verification dependencies installed. These are not product runtime dependencies.

## Logo and interface colors

The source logo is `public/logo.png`. Window, web, Windows and macOS application icons are generated from it. Preserve its alpha channel. After replacing it, run the following commands, including the separate 64 px asset not covered by the default icon generator:

```sh
npm run tauri -- icon public/logo.png
npm run tauri -- icon public/logo.png --png 64 --output tmp/icon-64
cp tmp/icon-64/64x64.png src-tauri/icons/64x64.png
cp src-tauri/icons/32x32.png public/favicon.png
```

The generator also updates existing mobile-size assets in the repository; supported product platforms remain Windows and macOS.

Brand accents for both themes are centralized in the color variables in `src/styles.css`. Red buttons use white text, and the dark theme uses charcoal backgrounds. Check text, control-border and keyboard-focus contrast when changing these colors.

## Dependencies, samples and submissions

- The default English README is at the repository root. Localized versions are in `docs/readme/README.{zh-CN,fr,es,ko,ja,de,pt}.md`; `README.en.md` also retains an English copy for existing links. Keep all eight languages and their navigation links synchronized when features, presets, build commands, support boundaries or licensing change. Other project documents are maintained in English.
- When upgrading PDF.js or changing fonts/WASM, review the corresponding licenses, sources and `licenses/pdfjs-assets.json`. See `scripts/make-font-sources.py` for the font-source archive generator and its pinned requirements; it is a development tool.
- Review the actual licenses of new code and assets, and keep distribution materials complete with `npm run notices`. Standalone CLI/worker distributions must also include the complete generated `third-party/` directory.
- Prefer reproducible samples generated by Rust examples. Do not commit users' original PDFs, keys, signing certificates or logs containing private document content. Provide a minimal sample you have permission to publish when reproducing an issue.
- Pull requests should explain the concrete problem, final behavior, test results and compatibility limits. Generated `target/`, `dist/`, `third-party/` and local `tmp/` directories are excluded from Git.

Public test records use synthetic samples or anonymous identifiers and exclude users' real filenames, local paths, original-document fingerprints and document content.

Check updater logic with `npm run test:updater`. See the [release guide](docs/RELEASING.md) for signing and ordinary development packaging.
