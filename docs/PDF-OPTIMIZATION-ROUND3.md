# 第三轮：图片保护、资源清理与黑白扫描编码

验证日期：2026-10-06 至 2026-10-07。产品版本：0.1.13，基线：0.1.12。原有 JPEG 质量、DPI 和矢量误差预算保持不变；保真仍保持原图片分辨率。

## 已进入引擎的策略

- 图片使用分析改为每个对象记录最大绘制尺寸与未知调用。图案、Type3、失败解析、循环或预算不足只影响相关图片的降采样；未知图片仍可在原尺寸重编码。无法限定继承环境时保守扩大保护。
- 外观批注、字段默认资源及特殊 Form 调用保护全部可达共享图片；这些图片不进行有损重编码。普通页面图片继续采用所选档位。附件不再关闭普通页面优化，附件、字段值、批注数据及外观继续保留。表单 / 外观批注的两项有损矢量优化仍采用整份保守保护。
- 按页面 / 自有资源 Form 的实际 Do 调用清理未使用的 XObject 入口。每个所有者收到私有资源副本，继承 / 共享字典保持可用；内容数组连续分析，没有自有资源的嵌套 Form 计入调用方资源使用。图案、Type3、软遮罩、内联二进制图片、未知操作或分析失败时跳过相关清理。其他资源类别暂未清理。
- 对支持解码的图片比较原组件样本及完整语义字典：尺寸、位深、颜色空间、Decode、遮罩、插值及其他元数据须相同。哈希命中后再次逐字节核对，不按 RGB 观感合并；标记图片保留独立身份。采用更小的原编码，并保持最早对象 ID，避免无意义的交叉引用开销。解码尝试有总工作量预算。
- 精确黑白图片加入 CCITT G4，与原编码、JPEG、Flate、Indexed 和 1 位 Flate 比较完整候选成本。只有样本全部为 0 / 255 才尝试，不阈值化抗锯齿、淡色文字或印章。支持 1 位 DeviceGray 原始 / 受限 Flate 输入；两种模式共享 G4 候选，每页图片模式仍只有一张图。

G4 使用 MIT 许可的纯 Rust [fax 0.3.0](https://github.com/pdf-rs/fax)，没有新增产品端 C 编译依赖。每个候选编码后先解码核对原样本；限制行宽，避免上游内部 16 位坐标差的边界。第三方许可文本进入生成通知。

## 黑白扫描、字体与 JPEG2000 实验

1729 × 2201 的精确黑白数字扫描样本：旧版保真 86,334 字节，新版 G4 77,974 字节，减少 8,360 字节（9.68%）；1 位与 8 位源图均输出相同大小，尺寸保持。图片模式像素无损导出 77,971 字节，仍一页一图。

- G4 输出在 Poppler 与 PDF.js 200 DPI 下与原件像素相同，另核对编码解码样本及奇数行宽、黑色起始、长游程、噪声与单图页面结构。
- macOS CoreGraphics 与旧版 1 位 Indexed 结果的 G4 渲染像素相同。CoreGraphics 对原 8 位与 1 位图的默认缩放显示不同，因此不将该结果写成对原件三种阅读器均逐像素相同。
- CID TrueType 子集开发实验明确使用自有测试 PDF 的 CID→GID 清单，字体程序 773,236 → 22,708 字节。CID 不变，重建 CIDToGIDMap；原内容字符串、宽度与 ToUnicode 保持。fontTools 独立检查使用字形及复合轮廓、度量、字形指令、cvt / fpgm / prep，通过；Poppler 与 PDF.js 渲染和文字提取相同。[subsetter 的映射要求](https://docs.rs/subsetter/0.2.6/subsetter/)必须遵守，尚未实现任意 PDF 字体的完整使用收集与表单编辑字符保护，未启用默认字体子集化。
- OpenJPEG 2.5.4 / Pillow 可逆 JP2 实验保持源样本，编码 1,102,308 字节左右，远大于本样本 G4。Poppler 正常，但 PDF.js 此测试出现尺寸警告与错误画面，未通过兼容性门槛，未接入默认引擎。

内联图片拆解、通用字体使用收集、循环资源子图归并、原单图跳过渲染、JBIG2 与更广泛特殊颜色输入留待独立实现和验收。本轮没有有损 JBIG2 字形替换。
