# 第六轮：原始颜色样本、默认映射与写入布局

日期：2026-10-07。实现版本：0.1.16；对照版本：冻结的 0.1.15 worker。本轮落实 [进一步研究](PDF-OPTIMIZATION-DEEPER.md) 中的前三项 P0，并补齐底层严格无损图片通路。图形状态精简、按调用展开 Form、成对降采样及自动字体子集尚未进入产品。

## 已实现的通用能力

1. **直接编码原始颜色分量。** 对受支持的 raw 或单层 Flate 图片，读取原始分量而不转换到 RGB；比较原编码、普通 Flate、固定及自适应 PNG 行预测。覆盖 1/2/4/8/16 位与 DeviceGray/RGB/CMYK、CalGray/CalRGB、Lab、ICCBased、Indexed、Separation、DeviceN 的受限结构。保留宽高、位深、ColorSpace、ICC Range、非默认 Decode、专色函数、Mask、SMask 与 Matte。胜出的原生编码再次反解，要求分量字节、位深与分量数完全相同。
2. **识别明确的默认 Decode。** 仅移除 DeviceGray/RGB/CMYK 中精确等于 `[0 1]` 重复数组的显式映射，支持数组及端点的间接引用。反相、Lab、ICC Range、Indexed 和其他映射保持。文档中出现 DefaultGray/RGB/CMYK 时保留所有显式 Decode，直至能够完整解释每个使用者的替代颜色空间；扫描超预算也采取同一保守行为。外部图像与受保护的交互外观在归一化之前跳过。
3. **比较完整文件的写入布局。** 保留当前编号布局，另外尝试压紧编号／清零代数，以及引用频率优先、字典类型辅助的排列。所有类型化引用同步更新，已有流的编码负载不解析、不改变。应用逆映射要求完整对象与 trailer 相同，候选写出后严格重读再核对。只有完整文件至少再少 65 字节的有效候选才替代当前最好结果；原文件继续参加最终体积选择。
4. **严格 Lossless 使用精确图片候选。** 底层 CLI/API 的 Lossless 现在可以使用精确行预测、调色板／位打包、G4 及受支持 JPEG 的系数域熵编码；禁止 JPEG 像素重新量化、降采样和矢量近似。界面的“保真”仍是 Fidelity：保留原图像素尺寸、使用原来的 JPEG 95／完整色度采样和既有矢量策略，不等同于整个文档严格无损。

原生分量新增工作限制为每张最多 4 MiB（含 PNG 行标签）、每份新增原始样本最多 16 MiB，累计尝试时间 4 秒后停止开始新的尝试；旧有的小型 8 位 CMYK 路径保持原资格。写入布局最多尝试两个额外候选，一次只克隆一份文档，限制 50,000 个对象及 64 MiB 编码负载／字典数据，另有操作次数和内联深度上限，8 秒后不再开始新的布局。时间限额是候选之间的软限额，单次编码／写入可能超过它；整个 worker 的原有超时和内存限制仍适用。

第一版不支持完整过滤器链，不移除看似不透明的遮罩，不调整带软遮罩图片的网格，也不改变专色或印刷颜色。未知编码、参数、尺寸或样本长度保留原数据。受 AP／表单等保护的共享图片连原始编码字节和显式映射都保留。加密和签名文档继续遵循原有入口限制。

实现位于 `crates/squeeze-core/src/native_samples.rs`、`image_encoding.rs`、`images.rs`、`writing.rs` 与 `lib.rs`；新增内部校验错误已进入八语言词典。没有新增运行时依赖或改变 JPEG、DPI 与矢量误差预算。

## 通用样本的新旧完整文件比较

17 类既有样本加 13 类新增样本，共 30 类。每类比较保留模式的 Lossless／Fidelity／均衡／更小与图片模式的无损／均衡／更小，共 210 对。所有新结果不大于 0.1.15，其中 67 组更小。写入布局保留原布局 206 次、选择压紧布局 4 次，说明排列没有统一赢家。

| 自建样本，保留／保真             | 0.1.15 完整字节 | 0.1.16 完整字节 |
| -------------------------------- | --------------: | --------------: |
| 16 位 RGB 渐变                   |         915,963 |          23,689 |
| 16 位 CalGray                    |         308,071 |           3,543 |
| 8 位 Lab 渐变                    |         249,702 |           2,588 |
| CalRGB                           |          11,300 |           2,861 |
| 两个分量均可见的 DeviceN         |           6,176 |           2,527 |
| CMYK ICC、Range 与反相 Decode    |         834,908 |          38,765 |
| RGB 显式默认 Decode              |           5,737 |           1,790 |
| 同网格软遮罩与 Matte             |          12,662 |           3,898 |
| 16 位 TIFF Predictor 2、间接尺寸 |           7,911 |           7,884 |

这些是有明确结构和行相关性的受控样本，不能把其压缩比例推广到一般照片。TIFF 16 位样本本身编码已经较好，本轮只有映射／结构的少量收益；不能说它证明了 TIFF 转 PNG 一定更小。表内数字是本轮实现的结果，不是上一份研究手工候选的结果。

Poppler 和 CoreGraphics 分别检查 210 个新结果及其源／基线；保真与严格无损的 60 个结果各自与源像素完全相同，图片模式的 90 个结果各自与旧版像素完全相同。pypdf 核对页数、页面框、保留模式文字、图片模式每页单图与无文字；全部源 SHA-256 不变。PDF.js 独立检查 60 个保真／严格无损结果，200 DPI 像素、文字内容和位置相同。逐像素结论均是在同一种阅读器内部比较，不是不同阅读器之间的比较，也不代表所有 PDF 都已覆盖。

最终再增加一类 DefaultRGB → ICCBased 的样本，ICC Range 为 `[0.2 0.8]` 重复三组，图像显式 Decode 为 `[0 1]` 重复三组。新旧两种模式七档共 14 次处理均成功，新版七个结果均不变大；映射与 ICC Range 保留，两个原生阅读器的保真／严格无损像素等于源，PDF.js 的两个像素／文字／位置检查通过。与主语料合计 **31 类、217 对**，Poppler／CoreGraphics 各检查 217 个新结果，PDF.js 检查 62 个精确对照。该额外样本直接使用最终包内 worker，记录位于 `tmp/round6-0.1.16/default-space/`。

最初生成的 Matte 样本错误地让遮罩和主图使用不同尺寸，原生阅读器拒绝了该样本；已隔离失效输入／结果，修正为同网格后重跑新旧 14 次处理及完整阅读器检查。它不是可接受的“阅读器告警”。TIFF 16 位输入另用独立 unsigned 16-bit 累加核对，避免依赖当前 pypdf 的按字节 Predictor 2 实现；Rust 测试使用已知跨字节／模 65536 值，PDF.js 和原生阅读器作额外核对。

原始记录位于忽略的 `tmp/round6-0.1.16/general/`。420 条新旧处理记录中，119 条既有基线复用上一轮并验证输入哈希，其余初始 301 次实际调用；修正样本的重跑另计，不将所有记录表述为 420 次全新执行。

## 后续范围

优先推进受限过滤器链和短 Contents 数组合并，然后是重复图形状态赋值与按调用次数选择 Form 展开。更大的原生样本可考虑分行编码和全局内存预算。自动字体子集、保留遮罩的成对降采样分别建立独立验收；前一阶段的失败反例仍保留。上述项目尚未实施，不算作 0.1.16 的能力。

默认颜色空间保护依据包括 [PDFium 的图片颜色选择与 Decode 处理](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/core/fpdfapi/page/cpdf_dib.cpp)；16 位 TIFF 样本预测可对照 [PDF.js predictor 实现](https://github.com/mozilla/pdf.js/blob/master/src/core/predictor_stream.js)。这些源码支持边界选择，实际兼容性结论来自上述测试。
