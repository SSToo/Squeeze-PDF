## 完整文件选择与发现的回归

保留模式先比较原有两个固定来源方案，透明图单独成为第三个固定来源候选，之后才尝试精确收尾。每个可选方案必须更小、严格重读且完整对象 / 引用与写入期预期一致，才能替代当前文件；源文件哈希和不覆盖提交规则继续保留。新的透明处理不对已经有损压缩的输出重复量化。

本轮曾发现透明图均衡候选为 12,293 B，旧版为 11,415 B。原因是新策略取代了原增强方案，失去了原先完整文件的对照。现在保留三套方案竞争，此例回退到 **11,415 B**。测试明确区分默认 Decode 与反向 Decode：允许证明语义相同的默认映射共享，反向映射仍须独立保留。

`advanced_optimization` 记录大图、精确共享、叶子、CMYK、字体、矢量和透明阶段；`strategy_candidates` 记录新增完整候选选择。`images` 仍是处理尝试记录，`output_images` / `size_after` 从最终序列化结果读取。未导出时仍指向实际原件。

- 原有 396 个新结果实际执行，全部与 0.1.20 输出逐字节相同，源哈希一致；因此继承前轮每种阅读器 1,152 页的验证结论。本轮没有声称重新渲染这 1,152 页。

## 桌面质量门槛与验收缺口

原生 WKWebView 曾分别执行冻结 / 新前端及 worker。细字页 small 的超采样候选为 93,821 B，直接方案为 94,153 B；Poppler 对源误差改善，CoreGraphics 关闭抗锯齿的对源误差却由 14.4517 增为 14.9102。这证明仅看体积或一个参考不能确认画质更好。

最终代码增加生产质量比较器，以直接 RGB 和超采样 RGB **两份固定参考**分别比较整页与边缘 RMSE。该细字候选对直接参考的整页 / 边缘误差为 18.1491 / 52.4637，原方案为 9.0481 / 24.7441；生产比较器已实际执行并拒绝候选，最终应采用直接方案。门槛独立覆盖模糊边缘负例、文件预算和取消先于 I/O。它是保守的编码 / 渲染候选筛选，不保证每种阅读器的对源误差一定下降。

桌面还补了 RGB 缓冲复用、后台 scheduler 定时器回退、独立 PDFWorker 的结束清理、取消错误归一、分块重放 / 缺块拒绝，以及按页数计算的渲染和 worker 总时限。一个会话失败后应释放忙状态；最终只原子导出一份结果，提交前再次核对原件哈希。

**真实 Tauri IPC 验证目前未全部完成。** 专用驱动已启动实际桌面程序，执行真实导入、计划、错误偏移拒绝与 abort，并进入取消测试；之后本机锁屏，系统工具明确返回 “The Mac is locked and automatic unlock could not unlock it”，WebView 回调暂停。该运行未完成任何完整任务，不能记作连续任务 / 取消重试通过。已请求手动解锁；Windows WebView2 和 macOS Intel 同样待实机验证。此前 loopback QA、单元测试或打包成功均不替代这些验收。
