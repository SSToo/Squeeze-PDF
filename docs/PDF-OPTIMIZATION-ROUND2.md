# 第二轮：Form 精度、JPEG 参数实验与编码缓存

日期：2026-10-06。版本：0.1.12。基线：0.1.11。范围对应研究计划的 D、Jpegli 对照、E 的受限 Form 精度与 L 的编码成本控制。

## 实际采用的改动

- 路径精度优化扩展到能够证明所有调用尺度的嵌套 Form。保留原来的约 0.0005 物理点 / 每轴误差预算，累计页面 UserUnit、cm 和 Form Matrix。用矩阵无穷范数的乘积作为保守上界，先建调用图再传播最大尺度，避免展开每个重复实例。
- 内容数组仍不逐流改写，但按连续图形状态分析它们对 Form 的调用。缺资源、无法解析、循环、外观、软遮罩、Type3、图案以及其他未知引用环境保护全部相关后代。分析具有操作数量限制与取消检查；只有更小的编码候选才提交。
- 该步骤发生在轮廓复用之前，使更多近似同形的轮廓得到相同的有限精度坐标，随后共享既有矢量 Form。保持 BBox、Matrix、透明组、资源语义与文字 / 矢量类型。
- 两种模式加入文件内 JPEG 缓存。完整像素哈希同时包含宽、高、通道与质量；最多 32 MiB / 256 个编码结果，任务结束后释放。只复用相同编码输入，不改变 JPEG 数据；报告新增 `jpeg_cached`。
- JPEG 参数实验保留为开发工具，默认编码器仍为 MozJPEG。各档 DPI、尺寸与 JPEG 质量沿用 0.1.11；保真维持原图片像素尺寸。没有新增产品运行时依赖。

## JPEG / Jpegli 对照

使用 8 份相同像素输入：两份原件的 5 个图片裁剪、2 张已渲染整页和 1 张带抗锯齿的彩色细字 / 细线样本。整页样本的 100 DPI 仅用于编解码比较，没有改产品 DPI。四个质量数字 95 / 85 / 72 / 60，每份输入比较 12 种配置，共 384 个 JPEG。

- MozJPEG：原配置、4:4:4 / 4:2:2 / 4:2:0、Annex K / MSSSIM / PSNR-HVS 量化配置、多扫描 Trellis。
- Jpegli：三种色度采样，以及接近原 MozJPEG 字节数的 4:4:4 编码。质量数字只作为编码器输入，不作为相等画质的证明。
- 指标包含 RGB RMSE、边缘 RMSE、8×8 亮度 SSIM、每个 32×32 区域的误差与最大区域误差；保存具体像素片段供视觉检查。严格实验筛选要求 SSIM、边缘和全部区域误差均不比基线差。这不是通用的人眼质量保证。

部分 JPEGli 照片裁剪在 q95 下小约 12%–18%，平均 / 边缘指标也可能更好；但没有更小的候选同时通过本次全部区域筛选。彩字样本的 JPEGli 4:4:4 q95 小约 11.2%，SSIM 更高，但边缘 RMSE 从 3.73 增为 5.32。MSSSIM 配置对该样本平均和边缘误差更低，体积收益约 0.1%，也未通过全部区域筛选。

因此本轮不把 Jpegli 或新的统一量化配置设为默认。后续可继续研究按内容与局部特征选择参数，使用更充分的文字 / 照片样本和感知指标，而不能只看全图平均分数或同一个质量数字。

开发期从 [Jpegli 官方仓库](https://github.com/google/jpegli) 构建，固定提交 `031a0077f5799a6041004267fc12b956c1f52a20`；其浮点处理、自适应量化与质量映射说明见 [官方 README](https://github.com/google/jpegli/blob/main/README.md)。MozJPEG 参数依据 [官方扩展说明](https://github.com/mozilla/mozjpeg/blob/master/README-mozilla.txt)。Jpegli、CMake 与相关源码仅保存在忽略的实验目录，不进入 App 或依赖通知。

## 验证与交付

- 全工作区 Rust 测试通过，覆盖 69 项不同测试；JPEG 示例重复运行了其中 4 项，共 73 次。新增嵌套变换 / 最大共享调用 / 数组连续状态 / 外观与遮罩 / 循环 / 未知引用 / 分析限额与取消、独立物理误差核对及缓存输入隔离 / 上限检查。收尾保护粒度调整后，20 项核心单元测试与严格 clippy 再次通过。
- 原有四种编码样本完成两种模式、三档、新旧两版本共 48 次压缩，24 对输出逐字节相同；Poppler 独立渲染与每页一图检查通过。
- 两份保真文件共 109 页使用 Poppler 100 DPI 渲染。Talvory 51 页逐像素相同，第 1 页 RGB RMSE 0.354；Orqavion 最大页面 RMSE 1.175，最大页面差异像素占比低于 0.1%。另用 PDF.js 200 DPI 检查 11 页，最大 RMSE 0.442，放大检查小字 / 轮廓及不同阅读器结果正常。Form 坐标发生受限舍入，因此不称全页严格无损。
- 最终桌面应用实际导入两份原件、完成保真批次，Downloads 的 `_compressed_5.pdf` 与命令行基准逐字节相同。原件 / 结果双栏预览正常，保持中文、浅色、保留内容 / 保真及 Downloads 设置。
- fmt、严格 clippy、TypeScript、多语言完整性与 PDF.js 损坏资源 / 表单批注渲染检查通过。
- macOS arm64 App / DMG 打包、磁盘校验、App 与 worker 的严格 ad-hoc 签名检查通过，worker 版本 0.1.12。Windows / macOS Intel 的实机构建、安装和正式签名公证未在本轮验证。

完整输入哈希、六组真实文件报告、JPEG 逐区域数据与编译记录、两种阅读器渲染、桌面输出核对及构建日志位于忽略的 `tmp/round2-0.1.12/`。本轮不要求已损坏的 Acrobat 生成对照，也不宣称证明优于 Acrobat。
