# 第一轮 PDF 压缩优化

日期：2026-10-06。版本：0.1.11；固定基线：0.1.10。对应原计划 A / B / C，以及 I 的对象流实验与写入改进。JPEG 质量、DPI、矢量精度预算与轮廓复用算法保持原设置。

## 已实现

- JSON 增加原件 / 候选的体积分类、逐阶段流字节与对象数量、耗时、图片编码候选及采用原因。新增只读 `squeeze audit` 命令。分类中的语法 / 字典 / 容器开销不等于可删除冗余；流按对象身份只计一次。`syntax_and_dictionaries` 是当前对象图以外的文件余量，也可能包含旧增量修订的数据，不仅是纯语法。
- 两种模式共享无损编码候选：Flate 原始样本、None / Sub / Up / Average / Paeth 固定预测、原三种及完整五种自适应预测、精确 Indexed 调色板和黑白 1 位打包。逐行对齐；不把灰色抗锯齿边缘自动变成黑白。比较成本包括图片字典、调色板与解码参数，保留模式继续比较原始编码。
- 透明遮罩仅尝试保持原位深、颜色空间与透明度样本的无损 Flate。ICC 图片继续保留原配置；没有扩大到 CMYK、特殊 Decode、Matte 等尚未支持的像素转换。高色数 RGB 快速跳过无效无损候选；纯色字节流只试直接 Flate，避免重复扫描大型不透明遮罩。
- 原有常规 RGB / Gray JPEG 增加系数域 Huffman 优化，比较顺序 / 渐进扫描；保持量化表、系数、尺寸、采样及 APP / COM 标记。携带 ICC 的 JPEG 可以使用此路径，仍禁止像素重编码。严格的 API / CLI `lossless` 保留模式仍沿用原图片编码。
- 对象流测试分组 100 / 250 / 500 / 1000 与等级 6 / 9。至少 1000 个优化后对象的文档采用 1000 / 9，小文档保持 100 / 6。写入增加缓冲并在提交前显式刷新；结果继续往返解析与检查原件哈希。

系数域“无损”指不再修改原 JPEG 量化数据，不表示恢复此前丢失的细节。图片模式的“清晰”无损指最后页面像素的编码，栅格化仍会改变文字、矢量和交互语义。

图片均衡 / 更小档中，大部分候选仍选择原有 JPEG，体积不变；灰度渐变均衡由 33,454 降至 31,120 字节。所有 24 对新结果均未变大。无损候选独立解码核对精确样本；48 份结果通过 Poppler 渲染。四份保留保真输出与原件渲染像素相同；图片输出保持每页一张独立图片。页面渲染与缩放本身也影响对原件的误差，不能把整个栅格 PDF 宣称为文档无损。

合成样本刻意覆盖缺失编码路径，收益不能外推到 Talvory / Orqavion 或其他商业文件。多候选在非纯色灰度 / 少色图上增加 CPU 成本，本轮没有承诺统一速度提升。

## 对象容器与写入实验

对已优化的 0.1.10 保真结果，仅改写对象流配置，每个输出重新读取并核对所有原流的字典与编码数据。改写本身的容器编号可能造成少量语法差异。

| 文件     | 100 / 等级 6 | 1000 / 等级 9 | 额外减少 |
| -------- | -----------: | ------------: | -------: |
| Talvory  |    6,994,607 |     6,983,516 |   11,091 |
| Orqavion |   51,096,318 |    51,083,571 |   12,747 |

阶段诊断还发现大量小对象直接写入临时文件会形成密集系统调用，现改为缓冲写入；修改前后的 Orqavion 保真 PDF 整份字节相同。计时受到同时构建、其他压缩与渲染任务影响，不据此给出速度倍数；桌面验证使用最终包内 worker。

## 复测入口与边界

```sh
cargo test --workspace --all-targets --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
node scripts/benchmark-round1.mjs tmp/round1-benchmark /path/to/0.1.10-worker
PDFTOPPM=/path/to/pdftoppm python3 scripts/verify-codec-benchmark.py tmp/round1-benchmark
cargo run --release -p squeeze-core --example write_variants --locked -- optimized.pdf tmp/write-variants
```

原始报告、所有候选与独立渲染检查保存在忽略的 `tmp/round1-0.1.11/`，不随产品分发。JPEG 单元测试核对量化表、完整系数、采样、标记及解码像素；还覆盖截断、尺寸不符与系数内存上限。调色板覆盖 1 / 2 / 4 / 8 位、非整字节行宽；遮罩覆盖精确 8 位样本。现有取消、创建竞争、交互内容、ICC、嵌套 Form、页面几何与附件回归继续运行。

第一轮未实施 Jpegli、按文字 / 照片选择 JPEG 参数、嵌套 Form 精度优化、字体子集化、保护粒度缩小、G4 / JBIG2 / JPX 或 Brotli。对用户这两份报告，后续仍应优先研究图片的同画质参数选择，以及 Orqavion 的 Form 绘制与资源开销；本轮数据支持这个方向，但不能预先保证压到 Adobe 的体积。
