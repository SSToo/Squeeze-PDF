# 第七轮：过滤器链、短内容流与完整文件回退

日期：2026-10-08。实现版本：0.1.19；冻结对照：修改前从当前工作区构建的 0.1.18 worker。保留 0.1.17 / 0.1.18 已有的文件大小与输出目录改动。本轮落实最新计划的第一批：完整候选与回退、常见可逆编码、短 Contents 合并、桌面渲染基线。图片编码分类、大图片分行处理、字体子集和其他 P1 / P2 尚未实施。

## 实现与边界

- **严格、分层、有界的流解码。** 支持 Flate、ASCII85、ASCIIHex、RunLength、LZW 及最多四层的受限组合；正确处理 Filter / DecodeParms 数组、null、间接引用，以及 LZW EarlyChange 0 / 1。Flate 必须有有效校验和与完整终止；ASCII 和 RunLength 要求有效结束标记；LZW 必须到达 EOD。拒绝部分解码结果、损坏编码、参数错配、未知参数与外部流。普通可逆重写暂限无预测器 / Predictor 1；其他预测器保留原编码。
- **图片文字包装剥离。** ASCII85 / ASCIIHex 包装的 JPEG、CCITT 和 Flate 图片可以只剥离外层。终端压缩字节及其对应 DecodeParms 保持，ColorSpace、Decode、Mask、SMask、位深和尺寸不改；不再次量化 JPEG、不解码或丢弃预测行。交互外观保护集重新按当前编号分析，受保护图片保持原编码。附件和 Metadata 不进入新增链重写。
- **绘图与资源分析共享严格解码。** 旧底层解码器可能返回错误流的部分结果，或无法正确处理间接 Filter / 参数数组。内容改写、资源清理、使用位置与 Form 分析改用严格通路。页面数组按精确字节连接，不人工重置 q/Q 或文本状态。无法确认的内容不会用于删除资源或调整绘图。
- **选择性合并短 Contents。** 新流只属于当前页面，原共享流不在原处修改。保留原数组顺序和精确连接的内容字节；同时核对精确连接和插入行分隔后的操作 / 操作数，跳过歧义注释、拆分词法、未闭合字符串、内联二进制图像及含特殊字典的内容流。
- **保护标签与内容流身份。** 发现 StructTreeRoot、StructParent(s)、MarkInfo、MCR / OBJR / StructElem 或 Stm 等绑定标记时跳过合并；结构扫描超预算或过深也跳过。新增候选不额外去重这类文档。独立检查 MCR /Stm 仍属于其 /Pg 页面原有 Contents 数组，不能只用像素相同作为标签正确的依据。
- **完整文件比较。** 先保留已验证的原压缩路径完整文件，再在该结果上运行新增精确流策略，必要时再清理、去重、选择写入布局。候选严格重读与引用 / 对象核对通过，且完整文件确实更小时才采用；变大或验证失败则恢复基线文件。取消仍中止提交。图片和有损路径优化只执行一次。报告新增 strategy_candidates 与 stream_optimization，记录尝试、选择、回退和跳过原因；size_after 来自实际胜出文件，包含对象流 / xref。

完整文件候选上限为 50,000 对象、64 MiB 编码流负载（同时受调用方限制约束）。新增链解码每层最多 4 MiB、每文档工作预算 16 MiB；合并每段最多 64 KiB、每页最多 256 KiB / 128 段、最多合并 128 页、文档解码预算 16 MiB。解码器逐块检查取消。两个新增处理阶段各有四秒软限额，现有写入布局仍有八秒软限额；这些在工作边界检查，不是单次编码 / 写入的硬中断。

实现位于 stream_filters.rs、coalesce.rs、stream_candidates.rs 和 lib.rs；更新相关内容分析调用。LZW 使用 Rust weezl 0.2.1，其原本已经在依赖树中，本轮成为直接依赖。运行时无需 qpdf 或 Python。JPEG / DPI / 颜色与既有矢量误差参数未降低，保真仍保留原图像素尺寸；Fidelity 不等于整个文件严格无损。图片模式仍是一页一张图片。

## 完整文件与阅读器验证

31 类既有原始样本、13 类新增编码 / 内容样本、两类真实 G4 包装与一类带 /Stm 的标签样本，共 **47 类、326 对**。每类比较保留模式 Lossless / Fidelity / 均衡 / 更小，以及 CLI 图片模式无损 / 均衡 / 更小；Stamp 共享外观样本的三个 CLI 图片组合依照已有接口限制排除，桌面渲染单独覆盖。

- **32 对更小，其余保持原大小，未出现体积退步。** 28 对选择新增完整文件候选；4 对由严格解析间接编码参数解锁既有处理。共享短流样本的四个保留档位均试出更大候选并正确保留基线。
- 最终验证集合包含 652 条新旧记录。319 条基线复用本轮冻结 worker 的已验证记录并核对源哈希，最后标签样本另执行七条基线；不将 652 条说成同一次全新调用。319 个主语料开发输出在标签保护修正后重新处理，完整字节不变。
- Poppler、CoreGraphics 各核对 326 个新结果与旧结果，在各自阅读器内像素完全相同；94 个保真 / 严格无损样本结果还分别与源相同。页框、页序、保留模式文字及标签身份、图片模式每页单图和无可选择文字通过。CoreGraphics 使用固定 200 DPI、关闭抗锯齿与插值，不能据此声称覆盖所有显示设置。
- PDF.js 独立核对 326 个新旧结果的像素、文字和位置；94 个保真 / 严格无损结果与源相同，最终主语料无 PDF.js 告警。结论是在同一种阅读器内部对照，不要求不同阅读器彼此输出相同像素。
- 独立 pypdf / ASCII 解码另外核对 24 个包装 / 外观保护结果：G4、JPEG、Flate 终端负载字节和参数语义相同，交互共享图片原编码不变，尺寸 / 位深 / 颜色保持。MCR 标签样本由 Rust 与独立 pypdf 双重检查引用关系。源 SHA-256 均保持。

## 桌面图片模式基线

在系统原生 WKWebView 中执行实际 src/rasterCompress.ts，使用本地 PDF.js 和原生 Canvas；只有 Tauri IPC 适配为本机 QA 服务。Rust prepare_raster 生成真实计划，冻结 / 新版 worker 读取同一套 manifest / RGB 文件并完成页面重建。覆盖文字 / LZW、照片包装、Matte 软遮罩、共享 Stamp 外观、短内容流、PNG 预测图片，三个档位共 **18 例**，同一桌面像素输入的两版完整 PDF 字节一致。

离屏 WKWebView 的 requestAnimationFrame 被定时调度代替，像素尺寸不依赖 devicePixelRatio。一次连续离屏运行在后续用例超时；最终以独立 WKWebView 进程完成全部 18 例。不能将其解释成已确认的产品故障，也不能据此声称已验证真实界面的连续任务、原生 Tauri IPC 或 Windows WebView2。QA 服务只监听 127.0.0.1，测试后关闭。

本轮建立 1 倍直接渲染的生产路径基线，没有将 CLI 的 2 倍超采样画质结论直接套用到桌面，没有启用新的默认渲染算法。放大渲染后缩小、按画质 / 体积选择策略仍需要下一批独立实验。
